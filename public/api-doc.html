Acme AI API 参考

使用 Acme AI 构建智能应用。本文档涵盖 v1 API 的全部端点、参数与响应。所有请求均通过 HTTPS 发送至下方 Base URL，每个响应均为 JSON 对象。

Base URL https://api.acme-ai.dev/v1
速率限制。免费版每分钟 60 次请求。速率限制随套餐升级，可通过 X-RateLimit-* 响应头查看当前配额。

快速开始

  1. 创建 API 密钥：在「控制台」创建密钥，并导出为 ACME_API_KEY 环境变量。
  2. 发送第一个请求：调用「聊天补全」端点。
  3. 解析响应：补全文本位于 choices[0].message.content。
  4. 处理错误：所有失败均返回结构化错误对象，参见「错误处理」。

身份认证

API 使用密钥进行身份认证。你可以在「控制台 → API 密钥」页面管理密钥，并通过 Authorization 请求头以 Bearer 方案传递：

Authorization: Bearer sk-••••••••••••••••••••

建议将密钥保存在环境变量中，由 SDK 自动读取：

export ACME_API_KEY="sk-xxxxxxxxxxxxxxxx"
请妥善保管密钥。切勿将 API 密钥嵌入客户端代码、公开仓库或任何用户可能提取的位置。密钥按账户计费并受速率限制——泄露密钥即泄露账单。

要求

  • 所有请求必须通过 HTTPS 发起。
  • 未携带有效密钥的请求将返回 401 authentication_error。
  • 密钥归属于你的组织，请求费用计入所属组织。

聊天补全

给定对话历史，模型返回下一条消息。这是对话与指令跟随场景的主要接口。

POST /v1/chat/completions

为给定的聊天对话创建模型响应。

请求参数

参数类型 是否必填说明
modelstring必需 使用的模型 ID。可用选项参见「模型」端点。
messagesarray必需 构成对话的消息列表。每项为包含 role（system、user 或 assistant）与 content（字符串）的对象。
temperaturenumber可选默认 1 采样温度，取值 0 到 2。值越高输出越随机，值越低越确定。
top_pnumber可选默认 1 核采样：仅考虑累积概率达到 top_p 的 token。建议只调整 temperature 或 top_p 之一。
max_tokensinteger可选默认 4096 生成的最大 token 数（含输入 token）。超出该上限的请求会被截断。
streamboolean可选默认 false 为 true 时，部分增量以 Server-Sent Events 流式返回，而非单个 JSON 响应。
stoparray | string可选 最多 4 个停止序列，API 在遇到这些序列时停止生成。返回文本不含停止序列。
userstring可选 代表终端用户的唯一标识，用于滥用监测与安全控制。

响应

  • idstring聊天补全的唯一标识。
  • objectstring始终为 chat.completion。
  • createdinteger补全创建时的 Unix 时间戳（秒）。
  • modelstring生成响应的模型。
  • choices[]array生成的补全列表，通常只有一个。
  • choices[].messageobject助手消息，包含 role 与 content。
  • choices[].finish_reasonstringstop、length 或 content_filter。
  • usageobjectToken 用量：prompt_tokens、completion_tokens、total_tokens。

流式输出

设置 stream: true 以接收增量结果。每个事件为包含部分补全的 data: 行，流以 data: [DONE] 结束。流式是低延迟聊天体验的推荐模式。

模型

列出并描述平台可用的模型。模型 ID 稳定——固定 ID 将持续提供同一模型，直至弃用（至少提前 90 天公告）。

GET /v1/models

列出你的组织可用的模型。

请求参数

参数类型 是否必填说明
limitinteger可选默认 20 返回的最大模型数量。
organizationstring可选 按组织 ID 过滤结果。

响应

  • objectstring始终为 list。
  • data[]array模型对象列表，每个对象包含 id、object、created 与 owned_by。
GET /v1/models/{model_id}

获取单个模型的元数据。

请求参数

参数类型 是否必填说明
model_idstring必需 要检索的模型，以路径参数形式提供。不存在时返回 404 not_found_error。

响应

  • idstring模型标识符，如 acme-chat-4。
  • objectstring始终为 model。
  • createdinteger模型创建时的 Unix 时间戳。
  • owned_bystring拥有该模型的组织。

错误处理

所有错误响应均为包含单个 error 键的 JSON 对象。该对象始终包含 message 与 type；code 与 param 在适用时设置。HTTP 状态码反映错误类别。

状态码错误码说明
400invalid_request_error请求格式错误或包含无效参数。
401authentication_errorAPI 密钥缺失、无效或已过期。
403permission_error你的密钥无权访问该资源。
404not_found_error请求的资源不存在。
429rate_limit_error请求过于频繁。请在 X-RateLimit-Reset 响应头指示的时间后重试。
500internal_server_error服务器意外错误。请使用指数退避重试（1s → 2s → 4s）。

重试建议

对于瞬时错误（429、5xx、网络超时），请使用带抖动的指数退避重试。切勿重试 4xx 错误——请修复请求。右侧示例展示了如何将结构化错误呈现给用户。

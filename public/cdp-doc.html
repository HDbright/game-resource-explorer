🛠 Chrome DevTools 调试连接说明

游戏资源管理器内置 Chromium 调试服务（CDP, Chrome DevTools Protocol）使用指南。
适用版本: v1.9.35+（设置页「开发者调试」开关）。 💡 设置页 CDP 卡片有「🔧 工具面板」按钮可打开交互式调试操作台

一、它是什么

应用基于 Electron(Chromium)。开启「开发者调试」后,应用会以 --remote-debugging-port 参数重启, 在本机开放一个 CDP 调试端口(默认 9222)。通过该端口,外部工具(Chrome DevTools、IDE 的 chrome-devtools 连接器、AI 调试助手等)可以连接并调试应用内所有页面:DOM 检查、控制台、网络抓包、性能分析、截图等。

应用启动后通常会有两个调试目标页面:

  • 主窗口 (page id 通常为 11) — 游戏资源管理器的 UI 界面（侧栏、主区、预览画布等）。
  • 网页视图 (page id 通常为 12) — 网络资源抓取模块的内置浏览器（WebContentsView）。

二、手动建立连接:操作完整流程

list_pages → select_page(id) → 操作 / 观察
1list_pages → 查看可用页面列表

首先需要知道当前有哪些可调试的目标页面。访问以下任一方式获取:

  • 浏览器打开 http://127.0.0.1:9222/json — 返回 JSON 数组,每个元素含 id、url、webSocketDebuggerUrl。
  • 终端执行 curl http://127.0.0.1:9222/json
  • 在 AI 连接器 / chrome-devtools MCP 工具中调用 list_pages 或 list_pages_and_get_ids。

典型输出示例:

[
  { "id": "11", "url": "file:///.../dist/index.html",     "type": "page", "title": "游戏资源管理器" },
  { "id": "12", "url": "https://some-game-site.com/xxx",   "type": "page", "title": "" }
]

记住目标页面的 id: 主窗口通常是 11, 网页视图通常是 12(具体以实际返回为准)。

2select_page(id) → 切换操作目标

这一步至关重要! 所有后续操作(截图、执行 JS、点击等)都作用于当前选中的页面。 如果不切换,默认操作的是主窗口(游戏资源管理器 UI),而不是你想调试的网页视图。

  • 想操作网络抓取的网页 → select_page(12)
  • 想操作应用主界面 → select_page(11)
💡 提示: 操作完网页后如果想回到操作应用侧栏/列表,记得 select_page(11) 切回主窗口!
3观察 + 操作 → 执行具体调试动作

选中正确的目标页面后,即可执行各种操作:

  • 截图 / 快照 — 用 take_screenshot 看画面,take_snapshot 看 DOM/a11y 树。
  • 执行 JS — 用 evaluate_script 在目标页内运行任意 JavaScript(读写 localStorage、调用引擎 API、模拟事件)。
  • 交互操作 — 用 click/type_text/press_key 模拟用户输入(仅对有 a11y uid 的 HTML 元素有效)。
  • 导航 — 用 navigate_page 让网页视图跳转到其他 URL。
  • 控制台 — 用 list_console_messages 查看目标页面的 console 输出和错误信息。

三、工具速查表

以下是 CDP 调试中常用的工具/端点及其用途说明:

工具 / 端点用途何时使用
list_pages列出所有可调试页面不知道当前有哪些 page,或忘记目标页面的 id 编号时
select_page(id)切换后续操作的默认目标页面想从主窗口(11)切换到网页视图(12),或切回来时。每次换目标都必须先调这个!

evaluate_script(expr)在目标页面内执行任意 JavaScript 表达式读写 localStorage / sessionStorage、调用页面内的引擎 API、读取/修改变量、模拟 DOM 事件、动态加载脚本等

四、关键注意事项

⚠️ 安全警告:调试端口无任何访问认证。开启后,本机任意进程都能连接并完全控制应用页面 (读取/修改内容、执行任意 JS、抓取输入等)。仅限本机开发调试,切勿在共享/公共环境开启,调试完成后请关闭开关。

操作顺序要点

  • 必须先 select_page(12) —— 否则一切操作都在主窗口(游戏资源管理器)上执行,可能误操作应用 UI。
  • 操作完网页想再操作侧栏/列表,记得 select_page(11) 切回主窗口。
  • canvas 页面没有 uid,本工具的 click / type_text 走不通,只能靠 evaluate_script(JS) + take_screenshot(截图验证) 组合来操作。
  • take_screenshot 加 filePath 参数可以直接保存截图到本地文件路径,后续可以用 present_files 或文件管理器直接查看。

技术细节

  • 端口仅在启动时生效:Chromium 的调试端口无法运行时动态开启,切换开关需要「保存并重启」。重启后旧的命令行调试参数会被自动过滤,统一由 userData/dev-cdp.json 标志文件控制。
  • 端口占用:若 9222 已被其他程序占用,应用可能启动失败或端口未生效,请更换端口(设置页可改)或释放占用。
  • 监听地址:调试服务只监听 127.0.0.1 回环地址,不对外网开放(但本机所有用户/程序可见)。
  • 与「网络资源抓取」的关系:CDP 调试的是应用自身窗口/页面;网络资源抓取页是应用内置的独立浏览器(WebContentsView),同样可通过 CDP 调试(在 /json 列表中可找到其 target,通常 id=12)。
  • 重启会恢复:开启后即使退出应用,标志文件仍保留,下次启动继续生效;关闭开关并重启后才会停止监听。
  • 连接器失联:应用重启期间端口短暂不可用属正常现象,等待重启完成后再连接。

五、常见问题 (FAQ)

问题处理
设置页状态显示「○ 待重启生效」说明标志已保存但当前进程未带调试参数启动,点「保存并重启」后即可。
curl 连接被拒绝端口未监听:确认开关已启用并重启过;检查端口号是否被占用(换端口)。
Chrome inspect 看不到目标确认 Configure 里已添加 127.0.0.1:9222,且端口号一致。
连接器提示无法连接确认目标地址用 ws://127.0.0.1:9222 或浏览器地址;不要填 https。
调试端口没开但设置显示已生效状态图标通过 TCP 探测端口判断,若被其他程序占用可能误报,请更换端口。
click/type_text 无反应目标可能是 canvas 页面(无 a11y uid);改用 evaluate_script + JS 事件模拟。
截图出来是空白/黑屏页面可能还未完全加载;先等待一下或 navigate_page 后稍作延迟再截图。
怎么知道哪个 id 是网页视图?list_pages 后看 url 字段:主窗口是 file:// 开头的 index.html,网页视图是 https:// 或 http:// 开头的外部网址。

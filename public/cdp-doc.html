🛠 Chrome DevTools 调试连接说明

游戏资源管理器内置 Chromium 调试服务（CDP, Chrome DevTools Protocol）使用指南。
适用版本: v1.9.31+（设置页「开发者调试」开关）。

一、它是什么

应用基于 Electron(Chromium)。开启「开发者调试」后,应用会以 --remote-debugging-port 参数重启, 在本机开放一个 CDP 调试端口(默认 9222)。通过该端口,外部工具(Chrome DevTools、IDE 的 chrome-devtools 连接器等)可以连接并调试应用内所有页面:DOM 检查、控制台、网络抓包、性能分析、截图等。

二、手动建立连接:操作完整流程

1启用调试服务
  • 进入应用 系统设置 → 开发者调试 (Chrome DevTools)。
  • 勾选「启用 Chrome DevTools 调试端口 (CDP)」,端口默认 9222(可改 1024~65535)。
  • 点击「保存并重启」——应用会自动重启并开放调试端口。
  • 重启后回到设置页,状态应显示 ● 已生效,可连接。
2验证端口已监听

打开终端执行(端口号按实际修改):

curl http://127.0.0.1:9222/json/version
# 期望输出包含:
# { "Browser": "Chrome/xxx", "webSocketDebuggerUrl": "ws://127.0.0.1:9222/devtools/browser/..." }

或在浏览器地址栏直接访问 http://127.0.0.1:9222/json,能看到应用各页面的调试目标列表。

3方式 A:用 Chrome DevTools 前端连接
  • 在 Chrome 浏览器地址栏输入 chrome://inspect → Configure… → 添加 127.0.0.1:9222。
  • 下方「Remote Target」列表会出现应用的页面,点击 inspect 即可打开独立调试窗口。
  • 或直接访问 http://127.0.0.1:9222/devtools/inspector.html?ws=127.0.0.1:9222/devtools/page/<页面id>(页面 id 见 /json 列表)。
4方式 B:用 WorkBuddy / IDE 的 chrome-devtools 连接器
  • 在 WorkBuddy 连接器(Connectors)中配置 chrome-devtools,目标地址填 ws://127.0.0.1:9222 或 http://127.0.0.1:9222。
  • 连接后即可由 AI 助手接管调试:打开页面、点击、填表、截图、抓取网络请求、执行 JS 等。
  • 若连接器需要具体页面,可先在 http://127.0.0.1:9222/json 找到目标页面的 webSocketDebuggerUrl。

三、工具速查表

端点 / 命令说明
GET /json/version浏览器级信息:版本、Browser WebSocket 调试地址。
GET /json (或 /json/list)列出所有可调试目标(页面/iframe/worker),含 id、URL、webSocketDebuggerUrl。
GET /json/activate/<id>将某页面置为前台/激活。
GET /json/close/<id>关闭指定页面。
GET /json/new?<url> (PUT)新建一个调试页面打开指定 URL。
ws://127.0.0.1:9222/devtools/browser/<id>浏览器级 WebSocket(Browser domain:target 管理、CDP 版本等)。
ws://127.0.0.1:9222/devtools/page/<id>页面级 WebSocket(Page/Runtime/DOM/Network 等全部 domain)。
curl -X PUT 'http://127.0.0.1:9222/json/new?about:blank'用命令新建调试页面。
curl -X GET 'http://127.0.0.1:9222/json/close/<id>'用命令关闭调试页面。

常用 CDP 命令示例(WebSocket 发送 JSON)

{ "id": 1, "method": "Runtime.evaluate", "params": { "expression": "document.title" } }
{ "id": 2, "method": "Page.captureScreenshot", "params": { "format": "png" } }
{ "id": 3, "method": "Network.enable" }
{ "id": 4, "method": "DOM.getDocument" }

四、关键注意事项

⚠️ 安全警告:调试端口无任何访问认证。开启后,本机任意进程都能连接并完全控制应用页面 (读取/修改内容、执行任意 JS、抓取输入等)。仅限本机开发调试,切勿在共享/公共环境开启,调试完成后请关闭开关。
  • 端口仅在启动时生效:Chromium 的调试端口无法运行时动态开启,切换开关需要「保存并重启」。重启后旧的命令行调试参数会被自动过滤,统一由 userData/dev-cdp.json 标志文件控制。
  • 端口占用:若 9222 已被其他程序占用,应用可能启动失败或端口未生效,请更换端口(设置页可改)或释放占用。
  • 监听地址:调试服务只监听 127.0.0.1 回环地址,不对外网开放(但本机所有用户/程序可见)。
  • 与「网络资源抓取」的关系:CDP 调试的是应用自身窗口/页面;网络资源抓取页是应用内置的独立浏览器,同样可通过 CDP 调试(在 /json 列表中可找到其 target)。
  • 重启会恢复:开启后即使退出应用,标志文件仍保留,下次启动继续生效;关闭开关并重启后才会停止监听。
  • 连接器失联:应用重启期间端口短暂不可用属正常现象,等待重启完成后再连接。

五、常见问题 (FAQ)

问题处理
设置页状态显示「○ 待重启生效」说明标志已保存但当前进程未带调试参数启动,点「保存并重启」后即可。
curl 连接被拒绝端口未监听:确认开关已启用并重启过;检查端口号是否被占用(换端口)。
Chrome inspect 看不到目标确认 Configure 里已添加 127.0.0.1:9222,且端口号一致。
连接器提示无法连接确认目标地址用 ws://127.0.0.1:9222 或浏览器地址;不要填 https。
调试端口没开但设置显示已生效状态图标通过 TCP 探测端口判断,若被其他程序占用可能误报,请更换端口。

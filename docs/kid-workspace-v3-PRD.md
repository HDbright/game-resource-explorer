## 1. 改造目标

一句话：把「得乐学苑」从"单一学生页 + 隐藏家长开关"改造为**可显式切换学生/家长双模式**的游戏化激励学习打卡模块，突出 ①学习打卡 ②虚拟奖励展示 ③家长布置与修改学习奖励计划和规则。

三个突出点的落点（与现有三大 Tab 的关系）：

1. **学习打卡**：保留「今日挑战」任务卡流（开始挑战→挑战成功→家长打星 1-3⭐→金币/经验），强化打卡状态可视化与连续打卡展示（P0-2）。
2. **虚拟奖励展示**：保留「成长奖励」钱包/等级/数字人/头像/商城/奖章墙，新增**统一奖励记录流水**（来源=任务完成/里程碑/家长发放/道具兑换），支持按类型/来源筛选（P0-3）。
3. **家长布置与修改学习奖励计划和规则**：新增**家长中心**独立视图，集中提供学习计划管理、逐任务奖励规则配置、奖励发放、修改日志（P0-4、P1），并与现有家长密码门禁、家长专属操作（移除/撤销/管理道具）衔接。

## 2. 现状事实摘要（PRD 依据，均已核实）

- **三大 Tab**：`今日挑战`（任务卡：开始挑战→挑战成功→星级弹窗→`grantReward`；可添加自定义任务）、`学习计划`（7 天周计划，套用均衡模板/清空/启停开关）、`成长奖励`（钱包 4 项、12 级数字人、8 头像、道具商城、兑换记录 `claimLog`、奖章墙 11 枚）。
- **家长模式现状**：顶栏「🔒 家长」按钮 → 4 位密码门禁（首次设置 `parentPwd`）→ `S.parentMode=true`；家长专属操作：任务卡「✕ 移除」「↺ 撤销(家长)」、商城「管理道具」；设置抽屉「奖励倍数 ×1/×1.5/×2」「修改家长密码」。
- **数据模型**：`S = { v:1, name, avatarId, themeMode, parentMode, parentPwd, rewardMult, coins, diamonds, crowns, exp, totalTasks, streak, bestStreak, lastDoneDate, lastStreakDia, bestAllFour, lastAllFourDate, lastWeeklyCrown, medals:{}, tasks:[], plan:{enabled, weekly[7]}, shop:[], claimLog:[], lastEnterDate, sampleLoaded }`。
  - 任务：`{ id, date, cat, title, target, unit, done, started, stars, carryover, planItemId, doneAt, rewarded }`。
  - 计划项：`{ id, cat, title, target }`；商城项：`{ id, name, cost, cur:coin|diamond, icon, note }`；兑换记录：`{ name, cur, cost, at }`。
- **奖励规则**：`rewardFor(stars)` = 基础 `10+星×5`（金币/经验同值），×全局 `rewardMult`；1/2/3 星=15/20/25；连胜 3/7/14/30 天送 5 钻石（`lastStreakDia` 防重）；周计划全完成送 1 皇冠（`lastWeeklyCrown` 防重）；全能四连记数；奖章由 `check(S)` 条件自动解锁。
- **每日滚动**：`rollover()` 把昨日未完成任务顺延到今天（`carryover++`），并按 `plan.weekly[今天]` 补齐今日计划任务。
- **向后兼容**：`loadState()` 用 `Object.assign(emptyState(), d)` 结构合并，缺失字段自动补默认值——新字段天然向后兼容。
- **冒烟测试**：`kid-wb-smoke-main.js` 37 项断言（进入工具/任务卡/星级奖励/成长奖励/兑换/计划/家长密码/撤销/主题/导出持久化），当前全过；改造后必须保持全过并新增断言。

## 3. 增量需求池

优先级约定：**P0 = 本次必须完成**；**P1 = 强烈建议，同版本完成**；**P2 = 可选增强，不阻塞发布**。

### P0-1 学生/家长双模式切换

**需求描述**：默认进入为**学生模式**；提供显式的模式标识与切换入口；**家长模式**为独立视图入口（家长中心），密码门禁保留（沿用现有 4 位 `parentPwd` 机制，首次设置/校验流程不变）。家长模式下顶栏显示「家长中心」标识并以底色区分（参考文档 3.2.1）。

**验收标准（可测试）**：
1. 首次进入默认学生模式，顶栏无「家长中心」标识、无家长底色。
2. 点击顶栏「🔒 家长」→ 首次弹出设置 4 位密码 → 设置成功后进入家长模式；已有密码时弹出校验，密码错误不进入并提示。
3. 家长模式下：顶栏按钮变金色「👨‍👩‍👦 家长」，旁显示「家长中心」标识（badge），顶栏/页面底色与家长模式区分（可测：存在 `parent-mode` 类或等价标识）。
4. 家长模式下可见家长专属操作（任务卡「✕ 移除」「↺ 撤销」、商城「管理道具」、家长中心入口）；学生模式下这些操作不可见。
5. 再次点击家长按钮或设置抽屉开关可退出家长模式，恢复学生模式。
6. `S.parentMode` 持久化，刷新/重进后保持。
7. 学生模式不可见「家长中心」内任何管理入口（计划编辑保持现状除外，见 P0-4）。

**涉及现有功能改动点**：
- `renderTopbar()`：家长按钮文案/金色态保留；新增「家长中心」badge 与「进入家长中心」入口（家长模式下显示）。
- `render()`：根容器增加家长模式类（如 `kid-wb parent-mode`），CSS 增加家长底色区分。
- `enterParentGate()` / `openPwdModal()`：复用，逻辑基本不变。
- 新增 `renderParentCenter()` / `openParentCenter()`（见 §6 布局）。

### P0-2 学习打卡强化

**需求描述**：强化打卡状态可视化与连续打卡展示。现状已有今日列表、进度环、连胜文案；本次新增**连胜打卡条**（近 7 天连续点亮）与**连胜里程碑进度**（距 3/7/14/30 天钻石奖励还差几天）。

**验收标准（可测试）**：
1. 「今天要处理」区新增打卡条，展示最近 7 天：按 `streak`/`lastDoneDate` 推导连续点亮最近 N 天（若 `lastDoneDate` 为昨天则点亮到昨天），未打卡日期灰显；当天已打卡显示"今日已打卡"态。
2. 打卡条随 `streak` 实时变化：完成一次任务后 `streak` 增加，打卡条点亮天数同步 +1（无需刷新）。
3. 展示连胜里程碑进度：当前 `streak` 距下一个里程碑（3/7/14/30）还差 N 天，格式如「距 7 天钻石奖励还差 2 天」；已达成全部里程碑则显示「已是满级连胜王」。
4. 里程碑达成时仍按现有 `grantReward` 逻辑发 5 钻石并 toast（不回退现有行为）。
5. 无打卡记录（`streak=0`）时展示引导文案，不报错。

**数据限制说明**：现有数据仅有 `streak`/`lastDoneDate`，可精确推导最近连续区间，但无法回溯更早的逐日历史；打卡条只展示最近 7 天。如需月度日历级精确展示，属 P2（新增 `doneDates[]` 历史字段，见待确认问题 Q6）。

**涉及现有功能改动点**：
- 新增 `renderStreakStrip()` 组件（渲染在 `renderToday()` 的今日区）。
- `grantReward()` 连胜逻辑**不改动**，仅读 `S.streak`/`S.lastDoneDate` 渲染。
- `renderRewardTab()` 现有连胜文案保留（可复用打卡条组件）。

### P0-3 虚拟奖励展示：统一「奖励记录」流水

**需求描述**：新增**统一奖励记录流水**，覆盖 4 类来源：`任务完成`（grantReward）、`里程碑`（连胜钻石/周皇冠/奖章解锁）、`家长发放`（P1）、`道具兑换`（现有 `claimLog`）。成长奖励 Tab 内提供「奖励记录」入口/区块，列表字段=获得时间/奖励类型/数量/获得项目/原因/来源，支持按**类型**、**来源**筛选（参考文档 3.3.2，时间范围筛选降为 P2）。

**验收标准（可测试）**：
1. 成长奖励 Tab 出现「奖励记录」入口，点击打开列表（弹窗或区块）。
2. 列表每条记录包含：时间（`fmtCn` 格式）、类型图标（金币/钻石/皇冠/奖章/道具）、数量、获得项目（如任务名）、原因、来源标签（任务完成/里程碑/家长发放/道具兑换）。
3. 完成一次任务 → 新增一条 `source=task` 记录（项目=任务名，原因=星级，数量=金币+经验）。
4. 连胜 3/7/14/30 天触发 5 钻石 → 新增一条 `source=milestone` 记录。
5. 周计划全完成得皇冠 / 奖章解锁 → 各新增一条 `source=milestone` 记录。
6. 商城兑换 → 新增一条 `source=shop` 记录，同时**保留**现有 `claimLog` 写入（双写兼容，见 §4）。
7. 家长发放（P1 完成后）→ 新增一条 `source=parent` 记录，含原因/备注。
8. 按类型筛选（金币/钻石/皇冠/奖章/道具/全部）、按来源筛选（任务完成/里程碑/家长发放/道具兑换/全部）生效。
9. 老用户已有 `claimLog` 数据在列表可见（迁移或合并展示，见 §4）。

**涉及现有功能改动点**：
- `emptyState()` 新增 `rewardLog: []`。
- `loadState()` 增加迁移逻辑（见 §4）。
- `grantReward()`：任务完成、连胜钻石、周皇冠、`checkMedals()` 奖章解锁处各写入一条记录。
- `claimItem()`：写 `claimLog` 的同时写 `rewardLog`。
- 新增 `openRewardLog()` / `renderRewardLog()`（含筛选控件）。

### P0-4 家长布置与修改学习奖励计划（家长中心核心）

**需求描述**：在**家长中心**提供「学习计划管理」与「逐任务奖励规则配置」：
- 计划管理：以 7 天列表集中展示计划任务，可**编辑**任务内容（类型/名称/目标数量）与**新增/删除**；修改后「发布更新」保存并即时生效（本地单机"发布=保存+生效"）。
- 逐任务奖励规则：每个计划任务可配置**独立奖励倍率**（默认 ×1，范围 0.5~3），与现有全局 `rewardMult` 叠加生效（参考文档 3.4.2，按现有 1-3 星体系作为完成质量分级：3 星≈优秀、2 星≈良好、1 星≈及格，星级倍率维持现状）。
- 约束：**当日已完成的任务不可删除**；**奖励下调需二次确认**；记录**修改日志**（时间+变更摘要）。

**验收标准（可测试）**：
1. 家长模式下家长中心出现「学习计划管理」；学生模式不显示该管理入口（学习计划 Tab 的添加/删除保留现状，学生可用）。
2. 计划管理列表展示 7 天全部计划项（名称/类型/目标/奖励倍率）；点击条目可编辑类型、名称、目标数量、奖励倍率，可新增/删除。
3. 修改后点「发布更新」→ 保存生效；学生视角（退出家长模式后）当天计划任务按新计划生成/展示（跨天由 `rollover` 生效，当天已生成任务不受删除影响）。
4. 删除计划项时：若该计划项**今天已生成任务且已完成** → 阻止删除并提示「今日已完成，明日可调整」；若今天已生成但未完成 → 允许删除并提示「今日已生成任务仍保留」。
5. 奖励倍率下调（新值 < 旧值）时弹出二次确认；确认后才保存。
6. 计划任务配置倍率后，完成该任务获得的奖励 = `rewardFor(stars)` 再乘该任务倍率（与全局 `rewardMult` 相乘，结果四舍五入保留 1 位小数），任务卡奖励预览与实际发放一致。
7. 每次「发布更新」追加一条修改日志（时间 + 摘要，如「周一：跳绳训练 目标 20→30，倍率 ×1→×1.5」），日志在家长中心可查看，学生模式不可见。
8. 所有新字段（计划项 `rewardMult`、`planLog`）对老数据缺省兼容，老计划无配置时按 ×1 行为不变。

**涉及现有功能改动点**：
- `openPlanItemModal()`：增加奖励倍率字段；新增**编辑已有计划项**能力（当前仅添加）。
- `plan.weekly[].items[]`：新增可选字段 `rewardMult`。
- `rewardFor(stars)` → 改为 `rewardFor(stars, task)`：`task.planItemId` 命中计划项且配置倍率时叠加。
- `renderPlanTab()`：家长模式下计划项显示倍率标签、编辑按钮。
- 新增 `planLog` 写入逻辑（集中在"发布更新"保存函数）。
- 新增 `renderPlanManage()`（家长中心内）。

## 4. 数据模型增量与兼容

> 原则：**只增不改**——新增字段全部可选、缺省即现状行为；`loadState()` 的结构合并天然兼容老数据；**不得删除/改名现有字段**。

**新增字段**：

```js
// S 顶层
rewardLog: [],   // 统一奖励记录流水
planLog: [],     // 家长修改日志

// 计划项（plan.weekly[].items[]，可选）
rewardMult: 1,   // 逐任务奖励倍率，缺省=1（行为同现状）

// （P2 可选）计划项 due 完成时限；S.doneDates[] 精确打卡历史
```

**统一流水条目结构**（新增）：

```js
{
  id: string,          // uid('rl')
  at: number,          // Date.now()
  type: 'coin'|'diamond'|'crown'|'medal'|'item',
  amount: number,      // 数量；道具兑换为花费，道具本身在 itemName
  itemName: string,    // 获得项目名（任务名/道具名/奖章名/里程碑名）
  project: string,     // 展示用获得项目（如「完成口算练习」）
  reason: string,      // 原因/备注
  source: 'task'|'milestone'|'parent'|'shop',
  meta: object,        // 可选扩展（如 shop 记录保留 cur）
}
```

**claimLog 兼容策略**（二选一，建议 A）：
- **方案 A（推荐）**：`claimLog` 保留字段与写入（`claimItem` 双写），新流水统一走 `rewardLog`；`loadState()` 时若 `rewardLog` 为空且 `claimLog` 非空，将旧兑换记录迁移为 `rewardLog`（`source='shop'`, `type='item'`），`claimLog` 不删除（防旧版本回退破坏）。
- 方案 B：仅展示层合并（读取时把 `claimLog` 并入列表），不迁移存储。缺点：筛选/统计需每次合并。

**loadState 向后兼容**：沿用现有 `Object.assign(emptyState(), d)`；新增字段在 `emptyState()` 中提供默认值即可。**导入功能**（`importData`）同样基于 `emptyState()` 合并，新字段自动兼容；导出 JSON 会包含新字段（旧版本预览脚本忽略未知字段即可，需回归确认 `kid-wb-export-html.js` 不受影响）。

- **后端 / 账号 / 多用户**：本模块是 Electron 本地单机应用（localStorage），无 `user`/`parent_bind`/`reward_log` 数据表；不做登录、账号体系、家长-学生绑定、云端同步。
- **参考文档中超出本次需求的其他游戏化系统**：智慧树、宠物/英雄养成、家园/战斗玩法、称号佩戴、背包/装扮、学科掌握度雷达图、勋章碎片合成等，均不纳入。
- **在线通知推送**：本地单机场景"学生端即时同步"以保存即生效实现，不做跨端推送。
- **移动端 H5 / 多端适配**：现有 CSS 已做 PC/窄屏适配，本次不新增移动端专项改造。
- **数据上云 / 加密存储 / 防刷风控**（参考文档 6.2）：本地单机无服务器侧风控，仅保留家长密码门禁与本地导出备份。

## 6. UI/交互说明

### 6.1 模式切换入口
- 保留顶栏「🔒 家长 / 👨👩👦 家长」按钮（现位置不变）作为**模式切换唯一入口**：学生模式点击 → 密码门禁（首次设置/校验）→ 家长模式；家长模式点击 → 退出回学生模式。
- 家长模式下，按钮旁新增「家长中心」badge（底色区分，如金色/紫色系），点击进入**家长中心**视图。
- 设置抽屉中「家长模式」开关与现有「修改家长密码」保留。

### 6.2 家长中心布局建议（新增独立视图，样式复用 `kid-card`/`kid-drawer` 体系）
家长中心顶部返回学生视图按钮；主体按区块排列：
1. **学习计划管理**：7 天列表（复用 `kid-plan-day` 布局），每项显示「名称 · 目标 · 倍率」+ 编辑/删除；底部「＋ 添加」「📋 发布更新」。
2. **奖励规则配置**：与计划管理合并呈现（计划项内嵌倍率），或独立小卡说明当前全局 `rewardMult` 与逐任务倍率叠加关系。
3. **奖励发放**：表单（类型/数量/原因必填/备注）。
4. **奖励记录**：筛选 chips（类型、来源）+ 列表。
5. **修改日志**：只读列表（时间+摘要）。

### 6.3 奖励记录列表设计
- 列表行：`[类型图标] 项目名 · 数量 [+N]  [来源标签]  时间`，原因/备注为次要行。
- 顶部筛选：类型 chips（金币/钻石/皇冠/奖章/道具/全部）+ 来源 chips（任务完成/里程碑/家长发放/道具兑换/全部）。
- 空态：复用 `kid-today-empty` 样式，文案如「还没有奖励记录，去完成今天的挑战吧 🎯」。

### 6.4 打卡条设计
- 位置：「今天要处理」标题行下方。
- 近 7 天圆点条：已打卡日=实心点亮（火焰/对勾），今天=高亮描边，未打卡=灰显；下方一行文案展示「已连续打卡 N 天 🔥 · 距 X 天钻石奖励还差 M 天」。

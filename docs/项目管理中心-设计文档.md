# 项目管理中心 — 设计与实现文档(补丁·113 / v2.4.3)

> 游戏资源管理器(Spine Viewer)新增「项目管理中心」顶级根目录模块,实现项目生命周期管理。
> 本文档说明页面结构、交互流程、数据模型与各模块职责边界,便于后续扩展与维护。

---

## 1. 需求总览

| # | 需求 | 落点 |
|---|------|------|
| 1 | 管理中心主页:汇总全部项目,显示名称/运行状态/最近更新时间,提供新增/备注/删除/进入详情 | `projectsPage.js` renderHome |

## 3. 交互流程

### 3.1 进入管理中心
侧栏点击「项目管理中心」→ `dispatchMenuDir` action=projects → 主页汇总 → `renderMainArea` 分发到 projects 分支 → `showPage('projects')` + `renderProjectsPage(mode='home')` → 进入后自动调用 `projects:status` 异步探测刷新各卡状态。

### 3.2 新增项目
主页「＋ 新增项目」(或侧栏根右键「新建项目…」)→ `newProjectDialog()` 模板表单(13 字段,路径字段带「浏览…」)→ 提交 → `addProject()`:
1. `ensureProjectsMenuRoot()` 幂等确保根节点
2. 写入 `state.projects`
3. `addMenuNode()` 在根下创建同名节点(action=project:<id>)
4. `saveState()` 持久化
5. 触发 `projects:navigate` 事件 → ui.js 进入详情页 + `renderTree()` 刷新侧栏

### 3.3 项目详情与服务启停
- 详情页「▶ 一键启动」→ `projectStart({kind:'all', cmd: launchMethod, cwd: rootPath})` → 主进程 spawn 子进程并登记 → 返回 ok/error → toast 反馈 → 重新探测状态。
- 「■ 停止」→ `projectStop` → 主进程 `taskkill /PID x /T /F` 杀整棵进程树。
- 按钮交互:点击后按钮置灰显示「⏳ 进行中…」→ IPC 完成 → toast(成功/失败原因)→ 状态徽章与运行状况行刷新。
- 状态优先级:最近操作失败 → `error`;进程表存活或 URL 探测可达 → `running`;否则 `stopped`。状态变化时回写 `state.projects[i].status`(仅 status 变化不刷新「最近更新时间」)。

### 3.4 编辑与同步
「✏️ 编辑项目」→ 同模板表单回填 → `updateProject()`:
- 更新 `state.projects`
- 若改名 → 同步侧栏菜单节点 `name/tooltip`(`updateProject` 内完成)
- `saveState()` 持久化
- `projects:navigate{refresh}` → 详情页 + 侧栏树同时重绘 → 三入口(主页/详情/导航)数据一致

### 3.5 删除项目
确认对话框(提示删除节点与条目、不影响磁盘文件)→ `removeProject()` → 移除项目配置 + 直接过滤删除菜单节点(含全部子目录,绕过根节点 locked 的祖先链锁检查)+ 清除全部条目 → 回到主页。

### 3.6 项目子目录与条目
- 资源文档页签「＋ 新建目录」/ 目录行操作(＋ 子目录 / ✏️ 重命名 / 🗑 删除)→ `addProjectFolder` / `renameProjectFolder` / `removeProjectFolder`(条目提升到项目根,不丢失)。
- 「＋ 新增条目」→ 名称 + 类型(文档/链接/文件)+ 内容 → `addProjectEntry`。条目打开:文档 → 内容弹窗;链接 → 外部浏览器;文件 → 系统打开。
- 侧栏点击项目子目录 → 详情页「资源文档」页签并定位到该目录。

## 4. 数据模型

### 4.1 projects 表(项目主配置,白名单四件套:CREATE/ALTER/readDb SELECT/writeDb INSERT)

| 列 | 类型 | 说明 |
|----|------|------|
| id | TEXT PK | uid('pj') |
| name | TEXT | 项目名称(侧栏节点名同步源) |
| status | TEXT | running/stopped/error(最近已知状态,实时探测优先) |
| description | TEXT | 项目描述 |
| root_path | TEXT | 项目根路径(服务 cwd) |
| access_url | TEXT | 访问地址 |
| website | TEXT | 网址 |
| launch_path | TEXT | 外部应用启动路径 |
| deploy_method | TEXT | 部署方式 |
| launch_method | TEXT | 一键启动命令 |
| frontend_cmd / frontend_url | TEXT | 前端服务配置 |
| backend_cmd / backend_url | TEXT | 后端服务配置 |
| remark | TEXT | 备注 |
| menu_node_id | TEXT | 关联侧栏菜单节点 id(名称同步/删除级联) |
| sort / created_at / updated_at | INTEGER | 排序与时间戳(秒) |

### 4.2 project_entries 表(项目资源/文档条目)

| 列 | 类型 | 说明 |
|----|------|------|
| id | TEXT PK | uid('pe') |
| project_id | TEXT | 归属项目 |
| folder_id | TEXT | 所属项目子目录(**菜单节点 id**,'' = 项目根目录) |
| name / type / content | TEXT | 条目名 / doc·link·file / 内容·地址·路径 |
| sort / created_at / updated_at | INTEGER | 排序与时间戳 |

### 4.3 侧栏结构(复用 menuNodes,不新建表)

| 节点 | action | parentId | 说明 |
|------|--------|----------|------|
| 项目管理中心 | `projects` | '' | 固定 id `__m_projects__`,locked,ensureProjectsMenuRoot 幂等自愈 |
| 项目节点 | `project:<pid>` | `__m_projects__` | 名称/提示随 updateProject 同步;删除项目时级联删除 |
| 项目子目录 | `projectfolder:<pid>` | 项目节点或上级目录 | 可无限嵌套;deleteProjectFolder 时条目提升到项目根 |

> ⚠️ 关键约束:`isMenuNodeLocked` 会检查祖先链,项目节点挂在 locked 根下,**删除项目/删除子目录必须直接 filter menuNodes**,不能走 `removeMenuNode`(会因根锁定拒绝删除)。

## 5. 模块职责与边界

| 模块 | 文件 | 职责 | 边界 |
|------|------|------|------|
| 数据层 | `electron/db.js` | projects/project_entries 表:CREATE、老库 ALTER、readDb SELECT(字段默认值)、writeDb 全量事务写 | 只做持久化,不感知 UI |
| 状态层 | `src/state.js` | projects/projectEntries 的增删改查、菜单节点创建/同步/删除、默认项目种子、自愈(ensureProjectsMenuRoot + 孤儿节点拉回根下) | 只改内存 state + saveState,不直接操作 DOM |
| 服务进程 | `electron/projectRunner.js` | 项目服务子进程的 spawn/登记/停止(taskkill /T /F)、HTTP(S) 健康探测、应用退出清理 | 只在主进程,通过 IPC 暴露 |
| 页面层 | `src/pages/projectsPage.js` | 主页/详情/资源文档三视图渲染、项目表单、条目表单、启停按钮状态机、状态轮询 | 不 import ui.js,通过 `ctx.actions` + `projects:navigate` 自定义事件驱动导航 |
| 导航层 | `src/ui.js` | 侧栏树渲染(projects 根/项目节点/子目录)、点击分发(projects/project:/projectfolder:)、主区页面切换、标签页(kind='projects')、右键菜单定制 | 持有页面状态(projectsHomeShown/currentProjectId/currentProjectFolderId/currentProjectDocTab) |
| 设置页 | `src/pages/settingsPage.js` | 菜单管理动态子内容(项目节点)、目标页面动作选项 page:projects、系统页面清单 | 只读展示 + 通用菜单编辑 |

### 解耦约定
- projectsPage 与 ui.js 之间**不循环 import**:页面内导航一律 `document.dispatchEvent(new CustomEvent('projects:navigate', {detail}))`,ui.js 模块级监听并驱动 `renderTree()/renderMainArea()`。
- 所有数据变更必须走 state.js 导出函数(内部统一 `saveState()` 防抖落盘),页面不直接改 `state.projects`。
- 运行状态(liveStatus)只在 `projectsPage.js` 模块内存缓存,**不落库**;落库的 status 仅是「最近已知状态」,每次渲染/刷新时用 `projects:status` 实时探测覆盖。

## 7. 扩展点(便于后续演进)

- **新增项目字段**:projects 表加列(白名单四件套同步)+ 表单字段追加即可,侧栏/详情自动渲染。
- **更多服务类型**:`projectRunner.js` 的 kind 目前 all/frontend/backend,可扩展为 `db/cache/worker` 等,IPC 参数不变。
- **部署命令模板**:launch_method 支持占位符(如 `{root}`/`{port}`),在 runServiceOp 中替换。
- **项目健康检查**:backendUrl/frontendUrl 已做 HTTP 探测,可扩展为「服务进程 + 端口 + 页面可达」三级判定。
- **条目类型扩展**:project_entries.type 可加 'image'/'video' 等,页面 openEntry 按类型分发。
- **多项目批量操作**:主页已聚合状态,可加「全部启动/全部停止」批量按钮(projectRunner.stopEveryProc 已就绪)。
